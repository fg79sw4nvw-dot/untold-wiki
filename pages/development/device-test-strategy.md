# Safari / iPhone 実機テスト方針

**状態：確定**  
**決定日：2026-09-16**  
**更新日：2026-09-16**

このページは、UNTOLDを当面Safari / PWAを主要な完成環境として開発し、iPhone実機で確認すべきタイミングをD/A/P0マイルストーンへ対応付ける開発運用上の正本である。

ネイティブアプリ化を先行して行うための文書ではない。UNTOLD v1はまずSafari / PWAで完成まで持っていき、必要な実機確認を節目ごとに行う。将来のiOS / Android / PC展開については `governance/platform-portability.md` の方針を維持する。

---

## 基本方針【確定】

- 実機テストを完成直前の一度だけに集中させない。
- ただし、設計や実装の細かな更新ごとに毎回実機確認する運用にもしない。
- 手戻りの種類が変わる節目ごとに、目的を分けた実機テストを行う。
- 基準実機はiPhone Safariとし、必要な段階ではホーム画面追加後のPWAでも確認する。
- D0 / D1 / D2 / D4 / D5の完了だけを理由に実機テストを行う必要はない。
- D3はUI・操作・主要システム仕様を扱うため、A2実装と組み合わせて実機確認する。
- P0-1 / P0-2 / P0-4は、単独では実機プレイを完了条件としない。

---

# 実機テストの6チェックポイント

## 1. P0-3進行中：最初の軽量実機確認【必須】

**現在の最優先チェックポイント。**

目的はゲーム内容の完成度評価ではなく、Safari / PWAという実行環境そのものが成立しているかを早期に確認すること。

P0-3のVercel公開環境が用意された時点で、少なくとも以下を確認する。

- iPhone Safariで正常起動する。
- 基本的なタップ・移動入力が成立する。
- 縦画面レイアウトに致命的な崩れがない。
- 現時点で実装済みの代表アセットが正常に表示される。
- Safari再読込後も起動できる。
- ホーム画面へ追加してPWAとして起動できる。
- Service Workerが実ブラウザで登録される。
- 一度取得した対象範囲について、想定するオフライン挙動を確認できる。
- アプリ終了・再起動で致命的な復帰問題が起きない。

この段階では全ゲームフローの完成を要求しない。

---

## 2. A1完成判定前：最初の本格的な縦切りプレイ【必須】

A1「基本プレイ縦切り完成」の達成判定前に、iPhone実機で縦切り範囲を最初から最後まで通す。

最低確認範囲：

- ゲーム開始から導入終了まで連続して進める。
- 通常移動。
- 会話。
- 調査。
- BOOK。
- 記録。
- 推理・条件達成。
- カード化。
- 収集。
- 依頼。
- マップ遷移。
- 日付・時間。
- セーブ・再開。

UNTOLDの基本ループ

`探索 → 情報収集 → 記録 → 推理 → 条件達成 → カード化 → 収集`

を最低1系統、実機上で完走できることを確認する。

---

## 3. D3終盤〜A2完成判定前：主要システム・UI統合確認【必須】

D3で主要システム・UI仕様が十分に固まり、それらをA2へ実装・接続した段階で実施する。

D3完了時とA2完了時に別々の実機テストを行うのではなく、原則としてこの1回へまとめる。

代表確認例：

- BOOKを開く／閉じる。
- 記録・思い出す・情報確認。
- フリーポケット。
- アイテム使用。
- 装備変更。
- スペル関連操作。
- MAP / ミニマップ。
- 施設利用。
- 各種戻る導線。
- セーブ・再開。
- 主要UI間の遷移。

特に以下を実機で確認する。

- ボタンサイズ。
- スワイプ。
- スクロール。
- 誤タップ。
- 入力競合。
- Safe Area。
- 戻る導線。
- 視認性。

---

## 4. A3完成判定前：世界移動・長時間・負荷確認【必須】

A3で製品版の地域・町・主要施設・移動網が成立した段階で行う。

短時間の機能確認だけでなく、**30分〜1時間程度の連続実機プレイ**を含める。

確認対象：

- 地域間移動。
- 町・屋外・施設の往復。
- マップ遷移。
- 船・確定済み特殊移動。
- カメラ。
- 大型マップでの操作感。
- 画像・アセットの読み込み待ち。
- 長時間プレイ後の重さ。
- Safariによるページ再読み込み等の発生有無。
- メモリ負荷。
- 発熱。
- バックグラウンド移行と復帰。
- 長時間のタッチ操作で無理がないか。

世界・描画・アセット構造の問題を、全コンテンツ投入前に発見することを目的とする。

---

## 5. A4完成判定前：初の全編実機プレイ【必須】

A4「全コンテンツ実装完成」の候補になった段階で、iPhone Safariで新規開始からエンディングまで最低1回通す。

目的は全不具合をこの時点でゼロにすることではなく、**製品版の全内容が実機上で一本のゲームとして成立しているか**を確認すること。

確認対象：

- 新規開始。
- 序盤・中盤・終盤。
- No.01〜No.99およびNo.0関連進行。
- 地域移動。
- 依頼・イベント。
- 情報導線。
- 自由探索による順序差。
- セーブ・再開。
- エンディング到達。

発見した問題はA5の全体QAへ引き継ぐ。

---

## 6. A5〜A6：本格QAと本番最終確認【必須】

### A5

A5では実機QAを本格化し、開始からエンディングまで複数回の通し検証を行う。

Safari通常タブとホーム画面追加版PWAの両方を確認対象とする。

少なくとも以下を組み合わせて確認する。

- オンライン。
- オフライン。
- アプリ終了 → 再起動。
- Safari終了 → 再起動。
- バックグラウンド → 復帰。
- 長時間放置後の復帰。
- セーブ → 再読込。
- ゲーム更新後の既存セーブ。
- 新規ゲーム。
- 終盤セーブ。
- エンディング。
- 代表的な条件差・順序差・日跨ぎ。
- 操作、表示、パフォーマンス、PWA基本挙動。

### A6

A6「リリース判定」ではテスト用環境ではなく、本番用ビルド・本番相当URLで最終確認する。

最低限、以下を確認する。

`新規開始 → セーブ → 再開 → 主要進行 → エンディング到達`

A6で新規機能を追加するのではなく、リリースを阻害する問題がないことを最終確認する。

# マイルストーンとの対応【確定】

| マイルストーン | 実機テスト方針 |
|---|---|
| D0 | 単独テスト不要 |
| D1 | 単独テスト不要 |
| D2 | 単独テスト不要 |
| D3 | A2と組み合わせて必須 |
| D4 | 単独完了時ではなくA4で全編確認 |
| D5 | 単独テスト不要。A6の前提として設計監査を行う |
| P0-1 | 単独テスト不要 |
| P0-2 | 単独テスト不要 |
| P0-3 | 現在の軽量実機確認を必須とする |
| P0-4 | 単独テスト不要 |
| A1 | 縦切り実機プレイ必須 |
| A2 | D3と組み合わせて主要システム確認必須 |
| A3 | 世界移動・長時間・負荷確認必須 |
| A4 | 新規開始からエンディングまでの初回全編確認必須 |
| A5 | 複数周回を含む本格実機QA必須 |
| A6 | 本番環境で最終実機確認必須 |

---

# 運用上の結論【確定】

実機テストは以下の6回を基本チェックポイントとする。

1. **P0-3：Safari / PWA成立確認**
2. **A1：基本プレイ縦切り確認**
3. **D3 / A2：主要システム・UI統合確認**
4. **A3：世界移動・長時間・負荷確認**
5. **A4：初の全編実機プレイ**
6. **A5〜A6：本格QA・本番最終確認**

必要な不具合修正後の再確認は随時行うが、通常の開発進行で毎コミット実機テストを要求しない。

# MAPプレビュー運用

## 状態

**確定**

## 目的

マップの座標仕様だけを見て配置を確定せず、実際のゲーム実装に近い見た目を画像で確認してから配置・導線を確定する。

また、マップの最終確認・Wiki同期・ゲーム本体実装を別作業として放置せず、原則として一続きの作業として完了させる。家具や施設の表示位置だけが更新され、当たり判定・NPC・イベントアンカーなどが旧座標に残る状態を防ぐ。

## 基本手順

今後、屋内・屋外を問わずMAPを新規作成または大きく変更する場合は、原則として次の順序で進める。

1. Wiki正本で、マップ寸法・タイルサイズ・主要施設／家具／地形・入口／出口・イベントアンカーなど、確認対象の仕様を整理する。
2. ゲーム本体に既存実装がある場合は、`main` の現在値と描画処理を確認する。
3. ゲーム本体のMAPプレビュー生成機構を使い、マップ全体を真上から見た**開発用静止画プレビュー**を生成する。
4. プレビュー画像で、配置、通路幅、入口・出口の視認性、NPCと家具の位置関係、イベント導線、当たり判定上の不自然さを確認する。
5. 修正案がある場合は、ゲーム本体へ先に反映せず、修正版プレビューを生成して比較する。
6. プレビュー上で配置を最終確定した後、Wiki正本を更新する。
7. **特別に作業を止める指示がない限り、そのまま同じ作業内でWiki確定仕様をゲーム本体へ同期・実装する。**
8. 実装時は座標データや描画だけで終えず、そのマップ変更に関係する当たり判定、通行可否、NPC位置・向き、会話判定、イベントアンカー、調査位置、入口／出口／階段／扉などの遷移・操作判定、スポーン位置、MAPプレビュー定義を確認し、必要な箇所を同時に同期する。
9. 実装後にMAPプレビューまたは実装値を再確認し、Wikiとゲーム本体に座標差分が残っていないことを確認する。
10. 実機確認が必要な段階では、表示・操作を確認し、プレビューでは発見できなかった視認性・操作性・画面サイズ依存の問題を確認する。

## 最終確認から実装までの一体運用

ユーザーがMAPプレビューを確認し、配置を「確定」とした時点をマップ設計の実装開始点として扱う。

- 原則として、**最終確認 → Wiki確定 → ゲーム本体同期 → 関連処理実装 → 実装後確認**までを一続きで行う。
- 「今回は設計だけ」「本体にはまだ反映しない」など明示的な停止指示がある場合のみ、指定された段階で止める。
- マップ変更に伴って座標依存の処理が存在する場合、見た目だけを更新して完了扱いにしない。
- 既存イベントやNPC導線が新配置と衝突する場合は、勝手に新しい仕様を補完せず、確定仕様の範囲で同期できる部分を実装し、追加判断が必要な箇所を明示する。
- 実装後は、Wiki・ゲーム本体・MAPプレビューの三者が同じ確定配置を参照していることを確認する。

## 自動プレビュー生成

ゲーム本体 `untold-game` にMAPプレビュー生成機構を置き、今後の標準方式として使用する。

- 実行入口：`npm run preview:map -- <map-id>`
- 生成処理：`scripts/render-map-preview.mjs`
- 出力先：`previews/<map-id>.svg`
- 初期対応MAP：`eld-library`

新しいMAPを追加する場合は、同じ生成機構から呼び出せるMAP定義を追加する。MAPごとに一時的なPython描画コードを毎回作る方式は標準運用にしない。

将来的には、ゲーム本体のMAPレイアウト定義をプレビュー生成処理から直接参照できる共通データ形式へ寄せ、ゲーム用データとプレビュー用データの二重管理を避ける。現段階で直接importできない実装については、プレビュー定義との差分が生じないよう変更時に同時更新する。

## プレビューの基準

- 単なるイメージ画像ではなく、可能な限りゲーム本体の実装値・タイル座標・描画比率を使用して再構成する。
- 既存実装の確認時は、現在の `main` を基準にする。
- Wiki仕様とゲーム実装が異なる場合は、その差を明示し、勝手にどちらかへ補完しない。
- マップ全体プレビューは、HUDやカメラで隠れない真上視点を基本とする。
- 必要に応じて、全体プレビューとは別に実機画面相当のカメラ範囲プレビューも作成する。
- 未確定の装飾や画像素材を、完成デザインであるかのように創作しない。未確定部分は簡易図形・仮表示で区別する。
- プレビューは仕様確認用であり、最終アートそのものとは扱わない。

## 確認項目

- マップ全体のバランス
- 移動可能な通路幅
- 家具・障害物・地形同士の干渉
- NPCとの会話位置
- カウンター越しなど特殊なインタラクションの成立性
- 階段・扉・入口・出口の視認性
- イベント開始地点と移動ルート
- 主人公のスポーン位置
- 画面端やHUDとの干渉
- Wiki・本体MAPデータ・プレビュー間の座標一致
- 変更した家具・施設に紐づく当たり判定やイベントアンカーの更新漏れ

## 実機確認との役割分担

プレビュー画像は配置設計の確認を早めるためのものとし、実機確認の代替にはしない。

- **プレビュー**：配置、寸法、導線、相対位置を確認する。
- **実装後確認**：Wiki、MAPデータ、描画、当たり判定、イベント等の同期漏れを確認する。
- **実機**：操作感、視認性、タップ／移動、HUDとの干渉、端末サイズ依存を確認する。

今後のMAP制作では、原則として **仕様整理 → 現状プレビュー → 修正版プレビュー → 最終確認 → Wiki確定 → 本体同期・関連処理実装 → 実装後確認 → 必要な段階で実機確認** の順で進める。

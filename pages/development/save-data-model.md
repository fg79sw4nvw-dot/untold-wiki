# P0-2 セーブデータ構造・バージョニング

**状態：P0-2完了**  
**決定日：2026-09-16**  
**更新日：2026-09-16**

このページは、UNTOLDを長期開発しても既存セーブを無自覚に破壊しないための、セーブデータの共通構造・保存原則・マイグレーション方針を定義する。

個別システムのゲーム仕様そのものは各正本を優先する。ここでは「何を永続状態として扱うか」「固定コンテンツとどう分離するか」「将来変更へどう追従するか」を扱う。

---

## 1. 基本原則【確定】

### 1.1 保存するもの

**プレイヤーの行動・選択・取得・時間経過・ランダム結果等によって変化し、固定コンテンツ定義だけから一意に再構築できない状態**を保存する。

例：

- 取得済みカード
- BOOK記録
- 進行済み依頼・イベント状態
- 現在日時
- 所持品
- 装備状態
- プレイヤー状態
- 探索済み・訪問済み状態
- 解放状態

### 1.2 保存しないもの

**固定IDから現行のコンテンツ定義を引けば再構築できる情報**は、原則セーブへ複製しない。

例：

- 指定カードの名称・説明・画像
- NPCの固定プロフィール・性格・通常配置定義
- 依頼の説明・開始条件そのもの
- アイテムの名称・効果定義
- 地域形状・町座標・固定マップ構造
- スペルの効果定義
- レシピの材料定義

これらをセーブへ複製すると、仕様更新時に古い定義がセーブ内へ残り続けるため、固定ID参照を基本とする。

### 1.3 派生値は保存しない

保存済み状態から安全に再計算できる値は、原則保存しない。

例：

- 現在時刻から求められる時間帯
- 所持カード番号から引けるカード名
- アイテムIDから引けるカテゴリ・固定効果
- NPC IDから引ける固定会話定義
- 現在位置と固定地形データから求められる判定値

ただし、ランダム抽選済み結果やプレイヤー操作によって変化した結果など、再計算するとロード前と結果が変わるものは保存対象とする。

## 2. セーブスキーマ【確定】

セーブデータには必ず `schemaVersion` を持たせる。

初期バージョンは以下。

```text
SAVE_SCHEMA_VERSION = 1
```

また、作成時点の共通コンテンツモデルのリビジョンを `contentSchemaVersion` として記録する。

`contentSchemaVersion` は診断・移行判断用のメタデータであり、数値が古いだけでセーブを即座に拒否しない。

固定IDの変更等によって実際のセーブ変換が必要な場合は、**SAVE_SCHEMA_VERSIONを上げて明示的なマイグレーションを行う。**

## 3. 現行SaveDataV1で保存する状態【確定・実装済み範囲】

ゲーム本体で現在実装されている範囲について、以下をSaveDataV1へ保存する。

- `gameTime`
  - 季節
  - 日
  - 時
  - 分
- `progressFlags`
  - 進行フラグの固定ID一覧
- `specifiedCards`
  - 取得済みNo.01〜99の番号
- `quests`
  - `active / completed` の依頼IDと状態
  - `inactive` は未記録を既定値として再構築可能なため保存しない
- `records`
  - BOOK記録
  - 記録グループ
- `conversationRecall`
  - 「思い出す」に必要な直近会話状態
  - 残り保持時間
- `inventory`
  - フリーポケット内の個体／素材スタック
- `equipped`
  - 装備中の個体とスロット
- `savedAt`
  - 保存時刻のメタデータ

## 4. 今後システム接続時に保存対象となる状態【確定方針】

以下は現時点で全てゲーム本体へ接続されているとは限らないが、**その状態がゲーム内で実在するようになった時点で、再構築不能な部分をセーブ対象へ追加する。**

### NPC・会話

保存対象：

- 日ごとのA/B/C会話進行に必要な状態
- 条件付き会話の進行・消費状態
- NPC固有イベントによって変化した状態

保存しない：

- 会話本文
- NPC固定プロフィール
- NPCの固定知識定義

### 依頼・イベント

保存対象：

- 開始済み／完了済み等の進行状態
- プレイヤー選択や多段階処理による途中状態
- 一度だけ成立する条件の消費状態

保存しない：

- イベント開始条件の定義
- イベント本文・固定演出データ

**D3で、標準の自動進行イベント・独立映像イベントの途中では保存しないことを確定済み。** イベント開始前または完了後の安全な通常状態を保存単位とし、標準セーブでは台詞番号、強制移動ウェイポイント、映像再生位置等のイベントカーソルを保存しない。詳細は `pages/systems/save-load.md` を正本とする。

### 時間・天候

保存対象：

- 現在日時
- 抽選済みの現在天候など、再抽選するとロード前と変化する状態
- 時間停止等の継続中効果で、現在状態から一意に復元できないもの

保存しない：

- 時間帯
- 天候遷移テーブル
- 季節定義

### 所持品・装備・スペル

保存対象：

- 所持個体
- 素材スタック数
- 装備中個体
- 所持スペルカード
- 個体固有または使用途中の状態がある場合、その状態

保存しない：

- 名称
- 固定効果
- レア度定義
- 装備効果定義

### プレイヤー状態

保存対象：

- HP
- 空腹度
- 状態異常
- 継続中の一時効果と残り時間
- その他、ロードによって失われるとゲーム結果が変わるプレイヤー状態

保存しない：

- 最大値等の固定定義
- 状態異常・効果そのものの定義

### 世界・探索・MAP

保存対象：

- 現在地または再開地点を復元するために必要な状態
- 訪問済み地域・町・主要地点
- MAPへ記録済みの探索状態
- 解放済みの隠し経路・特殊移動先等
- 一時的に世界へ配置した対象がある場合、その状態

保存しない：

- 地域境界
- 地形マスク
- 固定街道・橋・町座標
- 固定マップ画像

**D3で、通常時は `mapId`・正確なx/y座標・向き・`safeResumeAnchorId` を保存する方式を確定済み。** 保存座標が無効・範囲外・障害物内等になった場合のみ同一マップの安全アンカーへフォールバックする。詳細は `pages/systems/save-load.md` を正本とする。

### 解放・習得

保存対象：

- 永久習得したレシピID
- 使用可能になった機能
- 訪問・発見によって解放された転送先等
- プレイヤーの進行によって成立した恒久解放

保存しない：

- レシピ材料や完成物の固定定義
- 機能解放条件そのもの

## 5. 保存しない一時UI状態【確定】

原則として以下はセーブしない。

- 現在開いているタブ
- スクロール位置
- 選択中のリスト項目
- フェード途中の値
- アニメーションフレーム
- カメラ補間途中の位置
- 一時的なタップ候補
- 固定状態から再計算できるUIキャッシュ

ロード後に安全な通常状態へ再構築する。

ただし、ゲーム進行上の意味を持つ選択途中状態まで単なるUI状態として捨ててはいけない。進行結果に影響するものはゲーム状態側へ昇格して保存する。

## 6. ID運用【確定】

P0-1の共通データモデルと同じ固定IDを使用する。

- 表示名はセーブ参照キーに使用しない。
- NPC、依頼、場所、アイテム等は固定IDで参照する。
- 指定カードは番号を安定識別子として使用する。
- IDを変更する場合は、単純な文字列置換で済むと判断せず、既存セーブへの影響を確認する。
- セーブに保存済みのIDを変更する場合は、原則としてセーブスキーマを更新し、旧ID→新IDの変換をマイグレーションへ明示する。

## 7. マイグレーション方針【確定】

### 基本

セーブスキーマ変更は、原則として以下の順で行う。

```text
v1 → v2 → v3 → ... → current
```

複数バージョンを飛ばす専用変換を乱立させない。

### 変更時のルール

次の変更ではSAVE_SCHEMA_VERSIONの更新を検討し、既存セーブへ影響する場合は必須とする。

- 保存フィールドの意味変更
- 保存済み固定IDの変更
- 保存構造の分割・統合
- 既存状態から安全に既定値を決められない必須フィールド追加
- データ型変更

単に固定コンテンツの説明文や画像を変更しただけでは、セーブスキーマを上げない。

### データ保護

- マイグレーションでは、取得カード、記録、所持品等のプレイヤー所有状態を黙って破棄しない。
- 変換不能な状態がある場合、勝手に初期化せず明示的に扱う。
- 現行アプリより新しいセーブスキーマは読み込まず、`unsupported-newer-version` として拒否する。
- 必要な中間マイグレーションが存在しない場合は、`missing-migration` として拒否する。
- 壊れたJSONや必要構造を満たさないデータは `invalid-save` として扱う。

## 1. 現在の実証状況

2026-09-16時点で、`fg79sw4nvw-dot/untold-game/main` にカード実行用アセット管理と最小PWA基盤を実装済み。

### 実行用カード画像管理【実装済み】

制作正本は従来どおり `untold-wiki/assets` に置く。

ゲーム本体には以下を追加した。

- `asset-manifest.json`
- `scripts/sync-runtime-assets.mjs`
- `public/assets/cards/` を実行用生成先として使用
- `npm run dev` / `npm run build` の前に実行用アセットを自動同期

現存する指定カード画像について、アセットマニフェストで少なくとも以下を管理する。

- `assetId`
- 種別
- 対象コンテンツID
- Wiki側ソースパス
- Wiki側ソースURL
- Git blob SHA
- ファイルサイズ
- ゲーム側実行用パス

同期時はダウンロードした内容からGit blob SHAとファイルサイズを再計算し、マニフェストと一致しない場合はビルドを失敗させる。

これにより、同名ファイルの内容だけが変わった場合も無自覚に取り込まない。

`public/assets/cards/` は生成物としてGit管理対象外にする。

No.01 / No.55のカード定義は、Wikiの `raw.githubusercontent.com` を直接参照する方式を廃止し、以下の同一オリジン実行用パスへ変更した。

```text

/assets/cards/card-055-book-eating-rat.webp
```

したがって、製品版ランタイムはカード表示のためにWikiリポジトリへ直接アクセスしない。

### ビルド検証【成功】

GitHub Actions CIで、以下を含む現行ビルドが成功している。

## 2. アセットの正本と実行用データ【確定】

### 制作正本

仕様・採用画像・基準ビジュアル等の制作上の正本は、従来どおり `untold-wiki` 側で管理する。

### 実行用アセット

製品版ゲームが表示・再生するアセットは、**ゲームの実行環境から安定して取得できるリリース単位へ固定する。**

原則：

- 製品版ランタイムが `raw.githubusercontent.com` 等の制作リポジトリURLへ常時依存する構造は採用しない。
- 本番ビルドへ同梱するか、ゲーム用に明示した配信先へ固定する。
- PWAで必要なアセットは、キャッシュ戦略の対象として管理できる場所へ置く。
- 制作正本と実行用コピーは手作業で二重管理せず、マニフェスト＋同期処理で接続する。

現在は、**Wikiを制作正本、ゲーム本体の `public/assets` を実行用生成先**とする方式を採用している。

## 5. 最小PWA基盤【コード実装済み／公開環境検証待ち】

ゲーム本体へ以下を追加済み。

- `public/manifest.webmanifest`
- `public/sw.js`
- `src/pwa.ts`
- `index.html` からmanifestを参照
- デプロイ環境でservice workerを登録

### 現行キャッシュ方針

#### アプリシェル

service workerのinstall時に、現在配信されている `/` を取得し、HTML内の同一オリジン `src` / `href` を抽出してアプリシェルとしてキャッシュする。

これにより、Viteのハッシュ付きJS/CSS名をservice workerへ手動で固定しない。

#### 開始直後の代表カード

以下はコアアセットとして優先キャッシュする。

- No.01「忘れられた栞」
- No.55「書喰い鼠」

#### その他のカード画像

カード画像は安定URLを使用するため、`stale-while-revalidate` を採用する。

- キャッシュがあれば即表示する。
- オンライン時は裏で最新版を取得してキャッシュ更新する。
- オフライン時は既存キャッシュを使用する。

カード画像を同名のまま更新した場合でも、端末へ古い画像を永久固定しない。

#### Vite生成JS/CSS等

`/assets/` 配下の通常ビルドアセットはハッシュ付きファイルを前提に `cache-first` とする。

#### 画面遷移

navigationは `network-first` とし、通信失敗時はキャッシュ済み `/` をフォールバックとして使用する。

### 初回precache方針

99枚のカード、全地域、全NPC、音源等を初回に一括precacheしない。

- アプリシェル：優先
- 開始直後に必要な素材：優先
- カード・地域・イベント：必要時／到達時に取得
- 一度取得した素材：キャッシュ対象

この方針により、コンテンツ量が増えても初回起動を全アセット容量へ比例させない。

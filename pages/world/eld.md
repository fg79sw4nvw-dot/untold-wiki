# エルド

UNTOLD序盤の拠点となる辺境の町。山と森に囲まれ、旅人の中継地でもある。

## 雰囲気

- 古い石造りの建物と木造家屋が混在する。
- 長く静かに続いてきた町という印象。
- 手描き2DファンタジーRPG調、俯瞰視点、スマホ縦画面を基本とする。

## 町の基本構造

中央広場を町の中心に置き、そこから東西南北へ主要道路が伸びる。

- **中央**：中央広場。東西南北の道が交わる町の中心。人の待ち合わせや小規模な催しにも使われる。
- **南側**：街道から来た旅人・商人を受け入れる地区。宿屋、食堂、市場、馬留めなどを配置する。
- **西側**：森・丘や農地へつながる生活・生産地区。雑貨屋、住宅、作業場、小規模な畑を配置する。
- **東側**：比較的静かな地区。図書館、カードの館、東側住宅を配置し、東門から廃塔・遺跡方面へ続く。
- **北側**：古くからの町並みが残る旧市街。町長の家、教会、古井戸、古い住宅を配置する。
- **町外れ**：西側に廃屋、北西〜北側に祠を置く。

### 実装用マップ基準

町マップは **2048×2048px、64pxタイル、32×32グリッド** を基準とする。左上を `(0,0)` とし、中央広場・主要道路・城壁・4門・主要施設の基本位置と建物サイズは `pages/world/eld-layout.md` の座標を正本とする。

建物の外観デザイン・屋根形状・壁材・装飾などは後から調整できるが、主要施設の占有サイズと基本位置は原則固定とする。内部マップを持つ施設は、外観 footprint と内部マップ寸法を一致させる必要はない。

## 主要施設

中央広場、宿屋、雑貨屋、食堂、カードの館、教会、町長の家、廃屋、町外れの祠、市場、住居区、図書館。

図書館は主人公がブックを手に入れる重要な場所で、主人公は普段から自発的に手伝いをしている。

### 宿屋【確定】

- エルド宿屋は、**1階の受付・ロビー・食事スペース**を操作可能な内部マップとして用意する。
- 客室は操作可能マップとして作らない。
- 宿泊処理は受付から暗転して実行する。
- 宿泊後は明転し、宿屋1階ロビー内に設定する**専用の固定復帰地点**へ戻す。

### 図書館

図書館内部はエルド町マップとは別の屋内マップとして用意する。

- 司書（ELD-NPC-010）は原則として図書館内部に常駐する。
- 司書以外の一般NPCを、日常的な図書館利用者としては設定しない。
- 図書館が町で何のために存在しているか、住民からどのような施設として認識されているかは未確定とする。
- 書喰い鼠の依頼・夜間調査もこの図書館内部マップで行う。

#### 図書館地下室【確定範囲】

- 地下室は、記録文化喪失以前に**本・記録の保管、分類、修復等を行っていた旧記録管理施設**を基本とする。単なるエルド地域の記録庫には限定しない。
- 旧時代の未開への渡航・探索・交易等に関する記録や痕跡を含んでいた可能性を持つが、地下室そのものを未開専用施設とは確定しない。
- 現在の司書は、地下室の存在、古い書庫・保管室として使われていたこと、古い本・帳面・修繕用品等が残ることを知っており、過去に入った経験もある。
- ただし司書は、旧台帳や管理体系の歴史的価値、かつて存在した広域的な記録体系までは理解していない。
- 元荷運びが若い頃に地下室を扱っていた当時の司書・管理担当が、現在の司書だったとは固定しない。前任司書だった可能性も残す。

#### 主人公による地下室の再評価【確定】

- 主人公はゲーム開始時点から、エルド図書館に地下室が存在すること自体は知っている。
- 序盤では、地下室を**古い保管室程度**に認識しており、そこに特別な意味があるとは考えていない。
- 中盤手前で、①NPCから得る地下室の過去に関する断片、②エルド外で得る物的痕跡、③以前から知っていた施錠地下室、の3要素を主人公自身が結びつける。
- その結果、「ただの倉庫ではないのでは」と地下室を再解釈し、自発的に調べようとする。
- 司書から地下整理を依頼されることを、地下室調査の主な発端にはしない。
- 地下室到達時点で主人公が認識できるのは、**過去のオルバに現在より広い世界を前提とした航路・遠征・交易・採取の体系が存在した**ところまでとする。
- この段階では、未開の存在や記録文化封印の真相そのものまでは確定させない。

#### 地下室の解禁【確定】

- 主人公が地下室を調査すべき理由を得た後、司書へ地下室を確認したい意図を伝える。
- 主人公は普段から図書館を手伝っており、司書から一定の信頼を得ているため、司書は地下室への立ち入りを許可する。
- 地下室の鍵は**司書が管理している**。司書が管理用の鍵を使って施錠された扉を開ける。
- 地下室を普段施錠している理由は、古い保管物の管理と安全のためであり、秘密保持を目的としない。
- 司書自身は地下室の歴史的重要性を理解していない。
- No.02「開かずの小箱」は地下室の鍵とは関係させない。
- 初回解禁後は、主人公は地下室へ自由に出入りできるようにする。

#### 地下室探索と旧総合索引【確定】

- 地下室探索は、**現在の保管区画 → 旧管理体系の痕跡 → 旧総合索引発見**の段階を持たせる。
- 主人公は地下の棚・箱・管理設備に残る番号・分類表示と、レグナで得た指定遺物「旧移管票」（仮称）の管理記号が同じ体系であることを照合する。
- その照合から旧管理用の机・整理棚へ辿り着き、対応する記号を持つ引き出し等を調べることで旧総合索引を発見する。
- 旧総合索引は当時の日常的な管理業務で使われた資料であり、秘密の隠し部屋や二重底には隠さない。
- 旧総合索引そのものを**指定ポケットの遺物カード**にする。正式名称・番号は未確定とする。
- 発見直後にはカード化せず、まず開く・調べる・読むことで必要情報をBOOKへ記録し、重要性を把握した後にカード化できる流れとする。
- カード化により物理的な原本は消えるため、必要な情報取得はカード化前に行える設計を前提とする。
- ゲームマスターも過去に同じ原本を発見したが、持ち去らず、改変もせず地下室へ残した。
- 旧総合索引から読み取れる主要な調査系統は、①ポルトナ方面の航路・交易・輸送、②ブリガン島・スカルド方面の遠征・採取・資源収集、③セトラ方面の人員・物資・管理記録の3系統とする。
- セトラについては、この段階で戦争・衝突を直接示さない。
- これらとは別に、移管先不明、所在不明、廃棄、管理記録の突然の途絶等が大量に存在し、かつて広域的な記録体系が存在した後に大規模な欠落が生じたことを推測できる構造とする。
- 島への移動はポルトナ発着が基本であるため、索引が複数方面を示していても、地理的にポルトナが次の大きな調査拠点になりやすい構造とする。
- 旧総合索引の段階では、未開の存在や記録文化封印の真相そのものは明かさない。

#### 図書館1階レイアウト

図書館1階は **10×16タイル、640×1024px** を実装基準とする。1タイルは64px。タイル座標は左上 `(0,0)`、右下 `(9,15)` の0始まりとする。

- 入口は下辺中央。開口幅は **2タイル（128px）** で、`x=4〜5` に置く。
- 主人公の入館時スポーン位置は入口幅の中央、館内側。
- 上辺は壁1面すべてを本棚とし、`x=0〜9 / y=0` の **10×1タイル** とする。
- 左壁本棚は `x=0 / y=1〜6` の **1×6タイル**。
- 右壁本棚は `x=9 / y=1〜5` の **1×5タイル**。
- 中央の主要本棚は横向き **2列**。どちらも **幅5タイル** とし、奥側を `x=3〜7 / y=4`、手前側を `x=3〜7 / y=7` に置く。
- 奥側と手前側の間には `y=5〜6` の **2タイル（128px）** の通路を確保する。
- 追加の補助本棚を1列置き、`x=4〜8 / y=10` の **幅5タイル** とする。開始イベントでは使用せず、通常探索用の本棚として扱う。
- 司書カウンターは左下寄り、`x=1 / y=12〜14` の **縦3×横1タイル** とする。
- 司書の通常待機位置はカウンター左側の `x=0 / y=13` 付近とし、右向きで対応する。
- 地下室へ続く階段は **1×1タイル** のまま、左壁際の `x=0 / y=12` に置く。部屋中央側へ独立させず、カウンターの背面側に寄せる。
- 地下階段はゲーム開始時点では扉で塞がれ施錠されている。地下室調査の理由を得た後、司書の許可と司書管理の鍵によって解禁する。
- 右下の閲覧机は `x=5〜8 / y=13` の **幅4タイル** とする。
- 閲覧机の上側 `x=5〜8 / y=12` に、背もたれのない丸椅子を **4脚** 横並びで置く。着席時は下向き。
- No.01「忘れられた栞」の光は閲覧机の左寄り、`x=5 / y=13` 側に置く。調査時は主人公が机左側の `x=4 / y=13` 付近から右を向く形を基準とする。
- No.55「書喰い鼠」の夜間調査ポイントは左上寄りの床、`x=1 / y=1` 付近とする。上辺本棚と左壁本棚の角に近いが、壁や本棚そのものには重ねない。

##### 図書館開始イベント用アンカー

開始イベントの本整理・BOOK発見には以下を基準位置として使用する。

1. 整理①：`(8,1)`、上向き。
2. 整理②：`(5,1)`、上向き。
3. 整理③：`(2,1)`、上向き。ここで司書との会話へ入る。
4. 会話後の整理④：手前側中央本棚の左端、`(3,8)`、上向き。
5. その後は本棚左側 `x=2` 側を回り込み、奥側中央本棚の左端へ移動する。
6. BOOK発見位置：主人公 `(3,5)`、上向き。BOOKは奥側中央本棚の左寄り `x=3 / y=4` 側に置く。

家具の画像上の数px単位の位置や当たり判定は実装時に微調整してよいが、上記の**占有タイル、家具同士の相対位置、イベント上の機能位置**は維持する。

## NPC設計

NPCは原則として固有名を付けず、役割・立場・外見上の特徴などで区別する。内部管理用のIDは別途持たせる。

### 体型タイプ（確定・12種）

1. 少年
2. 少女
3. 若い男性
4. 若い女性
5. 成人男性
6. 成人女性
7. 中年男性
8. 中年女性
9. 老人男性
10. 老人女性
11. 旅人男性
12. 旅人女性

### 服装タイプ（確定・12種）

1. 町人服：一般住民、家事手伝い、無職の住民など
2. 商人服：雑貨屋、露店、市場関係者、行商人など
3. 宿屋・食堂服：宿屋、食堂、給仕など
4. 職人服：大工、鍛冶、修理屋、荷運びなど
5. 農作業服：農夫、牧畜、採集をする住民など
6. 狩人服：猟師、森に詳しい住民など
7. 旅装：旅人、冒険者、町外から来た人物など
8. 衛兵服：門番、警備担当など
9. 聖職者服：教会関係者など
10. 知識人・司書服：司書、学者寄りの人物など
11. 裕福な服：町長、裕福な商人など
12. 質素な老人服：引退した住民、老婆・老人など

体型タイプと服装タイプを組み合わせてNPCの基本外見を作る。服装だけで職業を完全に断定できるほど記号的にはせず、生活背景や職業が何となく推測できる程度にする。

## 基本ゲーム画面の基準

通常プレイ画面のHUD、主要操作ボタン、ミニマップ、会話HUD、移動入力、操作対象選択などの現行仕様は **`pages/systems/gameplay-ui.md` を正本**とする。

エルド固有ページでは、旧BOOK／CARD／MAPボタン配置などのUI仕様を重複管理しない。

- 通常フィールドの主要操作は「思い出す」「BOOK」を基本とする。
- 独立したCARDボタンは設けず、カードはBOOK内から開く。
- 独立したMAPボタンは設けず、右上のミニマップから拡大マップを開く。
- 現在目的とミニマップは、生存・環境HUDとは別UIとして配置する。
- ジェニーは常時HUDには表示せず、ショップや所持金確認など必要な画面で表示する。
- 写実的・写真風ではなく、温かい手描き2DファンタジーRPG調を優先する。

### 主人公表示・画面スケール

プレイテストまでは以下を全マップ共通の実装基準として使用する。詳細は `pages/systems/gameplay-ui.md` と `pages/development/implementation.md` を参照する。

- 主人公の内部表示高さ：**48px**。
- 主人公の表示幅：**40〜48px程度**を基準レンジとする。
- 当たり判定幅：**32px前後**を基準とする。
- 主人公位置は足元基準で管理する。
- マップごとに主人公の表示倍率を変更しない。
- マップごとにカメラ倍率を変更しない。
- 実画面上では、主人公の見た目の高さを **スマホ画面幅の約10%** とする。
- 論理画面幅は **480px** を基準とする。
- 1タイル64pxのため、横方向の表示範囲は **約7.5タイル**。
- 実機プレイテスト後に見え方を確認し、必要であれば共通スケールを一括調整する。

### 上部HUD

上部HUDの現行仕様は `pages/systems/gameplay-ui.md` を正本とする。

- safe areaを使用してノッチ／Dynamic Island等を避ける。
- HUD本体はプレイテストまで **高さ70〜80px程度** を基準とする。
- 左上1段目：HPバー。
- 左上2段目：空腹度バー。
- バーの右側：時間、季節、天候。
- 状態異常は発生時のみ小さなアイコン等で補助表示する。
- HUD本文系文字は **16〜18px程度** を基準とする。
- HP等の重要数値は **18〜20px程度** を基準とする。
- 現在目的とミニマップはこのHUDには含めない。

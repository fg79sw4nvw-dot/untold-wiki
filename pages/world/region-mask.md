# 地域ID・地域判定マスク 確定版

UNTOLDのワールドマップ上で使用する地域IDと、地域判定マスクの確定仕様。

地形IDは自然環境そのものを表し、地域IDはゲーム上のエリア区分を表す。両者は独立して保持し、同じ地形でも地域によってエンカウント、採取、BGM、イベント、カード条件などを変えられる構造とする。

## 地域ID【確定】

### カナタ平原・3地方

- `0` **エルド地方** / `eld_plains`
- `1` **レグナ地方** / `regna_plains`
- `2` **ポルトナ地方** / `portona_plains`

カナタ平原は広域に連続しているため、地形そのものを1地域とせず、町との地理的な関係を基準に3地方へ分割する。

3地方はいずれも地形ID上は `0` 草原であり、自然地理上は同一の**カナタ平原**に属する。

### 主島・地形連動地域

- `3` **ネモラ大森林地域** / `west_forest`
- `4` **カンデル山脈地域** / `north_mountains`
- `5` **フウラ高原地域** / `northeast_plateau`
- `6` **ミオ湿原地域** / `southwest_wetland`
- `7` **ガレド荒野地域** / `east_wasteland`
- `8` **ナーヴァ水系地域** / `inland_waters`

カナタ平原以外の主島主要地形は、原則として固有の大地形区分そのものを地域区分として使用する。

### 島地域

- `9` スカルド島地域 / `skald_island`
- `10` ボナペ島地域 / `bonape_island`
- `11` 北東無人島地域 / `northeast_uninhabited`
- `12` 西部無人島地域 / `west_uninhabited`
- `13` 南西無人島地域 / `southwest_uninhabited`
- `14` 南東無人島地域 / `southeast_uninhabited`

島は地形種類に関係なく、島単位で独立した地域IDを持つ。

### 海域

- `15` スカルド周辺海域 / `skald_waters`
- `16` ポルトナ沖海域 / `portona_waters`
- `17` ボナペ周辺海域 / `bonape_waters`
- `18` 西方海域 / `western_sea`
- `19` 北東海域 / `northeastern_sea`
- `20` 南方海域 / `southern_sea`

海は単一地域にまとめず、島・港・航路との関係を優先して周辺海域を設定し、残りの外洋を方角別に分割する。

海域の固有地理名は別途設定する。

## 地域境界の決め方【確定】

- カナタ平原の3地方は、エルド・レグナ・ポルトナを基準点として、各町からの距離を基礎に分割する。
- 町同士の中間付近を仮境界とし、川、街道、地形の見た目などに合わせて自然に調整してよい。
- 海域は、スカルド周辺、ポルトナ沖、ボナペ周辺を先に確保し、その外側を西方、北東、南方の外洋地域として分ける。
- 地域境界は地形境界と完全一致する必要はない。
- 同じ地域内に複数の地形が存在してもよく、同じ地形が複数地域にまたがってもよい。

## 地域判定マスク【確定】

- 地域判定には **4000×2500px** の地域IDマスクを使用する。
- 世界座標 `16000×10000px` に対して、**1px = 4×4ワールドpx** とする。
- 地域判定は主人公の足元中央1点を基準にする。
- 世界座標 `(x, y)` は、地域マスク上では `floor(x / 4), floor(y / 4)` に変換して参照する。
- 地域マスクの各ピクセル値は、上記の地域ID `0〜20` を直接保持する。
- 色による判定は行わず、ID値をそのまま参照する。
- 地域判定マスクも、地形判定マスクと同様にゲーム起動時に1回だけ読み込み、メモリ上に保持する。
- プレイ中は必要な座標の1点だけを参照し、地域IDを取得する。

## 地形IDとの併用【確定】

地形と地域は別データとして扱う。

例：

```json
{
  "terrainId": 0,
  "regionId": 1
}
```

上記は「草原地形にいるが、地域としてはカナタ平原のレグナ地方」を意味する。

用途の目安：

- 地形ID：自然環境、地形限定条件、採取条件、環境効果など
- 地域ID：エンカウントテーブル、地域限定イベント、地域BGM、カード条件、地域固有素材など
- 必要に応じて `terrainId + regionId` の組み合わせで条件を設定する。

## 将来の細分化

- 現時点では上記21地域を基本単位とする。
- 将来、特定カードやイベントのためにより狭い場所の判定が必要になった場合は、地域IDそのものを大量に増やすのではなく、サブ地域・地点ID・イベント範囲などを別データとして追加する。
- 地域IDはワールド全体の大区分として安定して使う。

## 今後の扱い

地域ID `0〜20`、カナタ平原の3地方区分、各大地形に対応する地域名、地域の分け方、4000×2500の地域判定マスク運用は確定事項として扱う。今後のエンカウント、採取、BGM、カード条件、地域イベント、航路などはこの地域IDを参照できる構造で設計する。

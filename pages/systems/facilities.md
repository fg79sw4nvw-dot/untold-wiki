# 施設共通仕様

## 基本方針【確定】

- 現段階で施設について決定する**機能・利用方法・受付フロー・営業時間などの基本仕様は、原則としてゲーム内共通仕様として扱う**。
- エルドでの検討を起点に決めた内容であっても、明示的にエルド固有とした事項を除き、同種施設へ共通適用する。
- 町・地域ごとの差は、共通仕様を上書きする**個別例外**として後から設定できる。
- 個別例外が設定されていない施設は、この共通仕様に従う。
- 外観、内部レイアウト、配置、担当NPC、固有イベント、品ぞろえなど、地域性や施設ごとの差を持たせる必要がある要素は個別仕様として扱える。
- 共通仕様を変更する場合は、すでに存在する同種施設にも原則として変更を適用し、明示的な個別例外だけを維持する。

## 仕様の分担【確定】

- 施設全体に共通する適用範囲・例外ルールは本ページを正本とする。
- ショップ、宿屋、価格、売買、施設利用料金など経済に関わる詳細は `pages/systems/economy.md` を正本とする。
- レシピの習得・保持・料理レシピ・製作レシピ・完成物のデータは `pages/systems/recipes.md` を正本とする。
- 各町における施設の位置、外観、内部構造、固有NPC、固有イベント等は各地域・町の正本で管理する。
- 同じ内容を複数ページへ重複記載せず、必要な場合は参照リンクでつなぐ。

## 宿屋：共通利用仕様【確定】

- 宿屋は原則として**24時間入館・宿泊受付可能**とする。
- 町・地域ごとに明示的な個別例外を設定した場合のみ、この共通仕様を上書きできる。
- 宿屋の受付担当NPCへ話しかけた際は、**「宿泊する」「話す」**を分け、通常会話を利用できる状態を維持する。
- 「宿泊する」を選択した場合は、`プラン選択 → 宿泊時間指定 → 内容確認 → 宿泊` の順で進行する。
- 宿泊内容の最終確認で確定した時点でジェニーを支払う。
- 支払い完了後は**暗転 → 指定時間だけゲーム内時間を進行 → 選択した宿泊プランに応じたHP・空腹度の回復処理 → 明転**の順で処理する。
- 実際の客室へ移動させるか、客室内を操作可能にするか等は共通仕様には含めず、各町・各宿屋の内部構造や演出に応じた個別仕様とする。
- 宿泊プラン、料金、指定可能な宿泊時間、回復効果などの経済・数値仕様は `pages/systems/economy.md` を正本とする。

## 情報屋：共通利用仕様【確定】

### 基本役割

- 情報屋は通常ショップには含めず、**有料で情報を提供するサービス施設**として扱う。
- 情報屋は推理の正解を直接販売する施設ではなく、**場所・時間帯・目撃情報・対象の特徴など、プレイヤーが組み合わせて推理に使える材料を提供する**。
- カード取得条件や依頼の正解そのものを、そのまま答える情報は原則として販売しない。
- 情報屋が**事実として提示する情報には意図的な嘘を混ぜない**。
- 噂や未確認情報を扱う場合は、未確認であることや情報の確度を発言内で明示する。
- 各情報屋が持つ情報プールは**情報屋ごとに個別設定**する。同じ情報を複数の情報屋へ割り当てること自体は可能とする。

### 受付メニュー

- 情報屋NPCへ話しかけた際の最上位メニューは、**「情報を買う」「聞き直す」「話す」**の3項目とする。
- 「話す」は通常のNPC会話として扱い、当日のA/B/C会話回数ルールに従う。
- **情報購入時・聞き直し時の会話は通常会話A/B/Cとは別枠**とし、通常会話回数を消費しない。

### 情報の選択と抽選

- プレイヤーは購入時に、まず**情報の範囲・カテゴリ・テーマ等を選択**する方式とする。
- 何を選択肢として提示するか、カテゴリ構造・一覧UI・検索方法などの具体的な選択方式は現時点では保留する。
- 選択後、その選択範囲に含まれる**未取得情報から1件をランダム抽選**して提供する。
- 同じ選択範囲では、候補を一巡するまで同じ情報を重複抽選しない。
- 抽選候補が0件の場合は購入不可とし、料金は発生しない。
- 候補が残っている場合でも、**残り件数はプレイヤーへ表示しない**。
- 購入前に表示するのは、選択した情報範囲と料金までとし、実際にどの情報が抽選されるかは購入後まで表示しない。

### 情報プールの解放・取得履歴

- 各情報には、必要に応じて**ストーリー進行、依頼進行、地域到達、カード取得などの個別解放条件**を設定できる。
- 解放条件を満たした情報は、対応する情報屋の情報プールへ追加される。
- 一度解放された情報は原則として候補に残り続け、取得済みになった時点で抽選候補から除外する。
- 期間限定情報が必要な場合だけ、個別例外として販売期間・有効期間等を設定できる。
- 情報屋から購入した情報の**取得履歴は全情報屋で共通管理**する。
- 一度いずれかの情報屋から取得した情報は、別の情報屋に同じ情報が割り当てられていても抽選候補から除外する。
- ブックに**同一情報ID・同一情報グループに属する情報がすでに記録済み**の場合、その情報も購入時の抽選候補から除外する。
- 取得済み情報や、記録済みで候補除外された情報は、後からブック内の記録を削除しても抽選候補へ戻さない。
- 単に過去に聞いただけで取得履歴にも記録にも残っていない情報は、それだけを理由に抽選候補から除外しない。

### 料金・購入処理

- 情報の料金は**個別情報ごとではなく、プレイヤーが選択する情報範囲ごとに設定**する。
- 購入前に、その選択範囲の料金を表示する。
- 購入フローは、`情報範囲を選択 → 価格確認 → 購入確定 → 料金支払い → ランダム抽選 → 情報を聞く` を基本とする。
- 所持ジェニーが不足している場合は購入できず、料金も発生しない。
- 条件を満たし、購入可能な情報が残っている限り、**購入回数そのものには共通の回数制限を設けない**。
- 1件の情報を聞き終えた時点で情報屋の会話・施設メニューを閉じる。続けて購入する場合は、再度情報屋NPCへ話しかける。
- 通常ショップ用の**割引券・クーポンは情報購入には使用できない**。
- 情報料を割り引く仕組みを作る場合は、情報屋専用の個別仕様として扱う。
- プレイヤーから情報屋へ情報を売る機能は設けない。

### 情報の提示・記録

- 購入した情報は、**情報屋NPCの発言として会話形式で提示**する。
- 購入した情報は自動でブックへ記録しない。
- 情報を話し終えた直後には、情報屋NPCが**必要なら記録しておくよう自然に促す一言**を入れる。
- 促しの具体的な文面は、各情報屋NPCの性格・口調に合わせた個別会話として設定する。
- 購入直後の情報も、後述の「聞き直す」で再提示された情報も、**通常のNPC会話と同じ記録UIから文単位で任意に記録可能**とする。
- 情報購入・聞き直し時の会話も、`pages/systems/recording.md` で定める通常のNPC会話と同様に**「思い出す」の対象**とする。

### 聞き直し

- 購入した情報は、**購入時刻から6ゲーム時間だけ無料で聞き直せる**。
- 聞き直し可能時間は情報ごとに個別管理し、新しい情報を購入しても、それ以前に購入した情報の期限は延長しない。
- 専用の聞き直し期限は購入時刻を基準とし、聞き直したこと自体では延長しない。
- 「聞き直す」では、まだ6ゲーム時間以内にある購入済み情報だけを候補として表示し、その中からプレイヤーが任意の情報を選んで再度聞ける。
- 聞き直し一覧の具体的なUI・表示名は現時点では保留する。
- 聞き直しを終えた時点で情報屋の会話・施設メニューを閉じる。
- 6ゲーム時間を過ぎた情報は専用の「聞き直す」からは再提示できないが、取得済み履歴は残り続け、抽選候補には戻らない。
- 「思い出す」側で会話セッションが保持されている場合は、専用の聞き直し期限とは別に、既存の「思い出す」ルールに従って参照できる。

### 営業時間

- 情報屋の営業時間は**情報屋ごとに個別設定**する。
- 営業時間外は新規の情報購入を利用できない。
- 専用の「聞き直す」も営業時間内だけ利用可能とする。
- 購入情報の6ゲーム時間の聞き直し期限は、営業時間外でも通常どおり進行し、閉店中は停止しない。

## 食堂：共通利用仕様【確定】

### 基本役割

- 食堂は通常ショップには含めず、**食事提供と調理依頼を扱うサービス施設**として扱う。
- 各食堂の通常メニューは**店舗ごとに個別設定**する。
- 通常メニューとは別に、プレイヤーが習得済みの料理レシピを使って調理を依頼できる。
- レシピの習得・保持・料理効果等の詳細は `pages/systems/recipes.md` を正本とする。

### 受付メニュー

- 食堂NPCへ話しかけた際の最上位メニューは、**「食事する」「調理を頼む」「話す」**の3項目とする。
- 「食事する」は、その食堂の通常メニューから料理を注文する。
- 「調理を頼む」は、習得済み料理レシピから1種類を選び、必要素材を渡して調理を依頼する。
- 「話す」は通常のNPC会話として扱い、当日のA/B/C会話回数ルールに従う。
- **「食事する」「調理を頼む」は通常会話A/B/Cとは別枠**とし、通常会話回数を消費しない。

### 注文・調理単位

- 通常メニューの**「食事する」は1回の注文につき1料理**を扱う。
- 「調理を頼む」では、**1回の依頼につき1種類の料理レシピだけ**を選択する。
- 選択した料理レシピは、1回の依頼で**複数食を調理可能**とする。
- 調理数量に共通の上限は設けない。
- 必要素材は、**レシピ1食分の必要量 × 指定数量**を必要とする。
- 異なる料理レシピを1回の調理依頼へ混在させることはできない。

### 完成後の選択

- 1食だけ注文・調理した場合は、完成後に**「すぐ食べる」「持ち帰る」**のどちらかを選択する。
- 複数食を調理した場合は、完成後に**「すべて持ち帰る」「1つだけ食べる」**のどちらかを選択する。
- 「1つだけ食べる」を選択した場合は1食をその場で消費し、残りをすべて持ち帰る。
- 持ち帰る料理は、すべて**食料カテゴリ**のフリーポケットへ収納する。
- 持ち帰りに必要な食料カテゴリの空き枠が不足している場合は、その受け取り方法では最終確定へ進めない。
- 持ち帰り可能かどうかは、**注文・調理確定前に判定**する。

### 確定・消費タイミング

- 基本フローは、`料理／レシピ選択 → 数量指定（調理依頼のみ） → 必要条件確認 → 受け取り方法選択 → 最終確認 → 支払い・必要素材消費 → 調理 → 効果適用または食料カード取得` とする。
- **最終確認まではジェニーも素材も消費しない**。
- 所持ジェニーや必要素材が不足している場合は確定できず、消費も発生しない。
- 調理依頼で複数食を作る場合は、指定数量分の必要素材をまとめて消費する。

### 時間処理

- 食堂で「すぐ食べる」または「1つだけ食べる」を選択しても、**ゲーム内時間は進行しない**。
- 食堂で調理を依頼しても、**ゲーム内時間は進行しない**。

### 営業時間

- 食堂の営業時間は**店舗ごとに個別設定**する。
- 営業時間外は「食事する」「調理を頼む」を利用できない。

### 追加サービス

- 食堂には、配達・宴会・特殊加工などの**追加サービスを共通仕様としては設けない**。
- 必要な追加サービスは、食堂ごとの個別仕様として設定する。

## 作業場：共通利用仕様【確定】

### 基本役割

- 作業場は通常ショップには含めず、**素材を使った製作を依頼するサービス施設**として扱う。
- 作業場の標準機能は**製作のみ**とする。
- 修理・強化・加工・鑑定は、作業場の標準機能には含めない。
- 作業場には食堂の通常メニューに相当する**レシピ未習得で利用できる通常製作品を設けない**。
- 製作は、プレイヤーが習得済みの製作レシピからのみ依頼できる。
- 製作レシピの習得・材料・完成品カテゴリ等の詳細は `pages/systems/recipes.md` を正本とする。

### 受付メニュー

- 作業場NPCへ話しかけた際の最上位メニューは、**「製作を頼む」「話す」**の2項目とする。
- 「製作を頼む」は、習得済み製作レシピから製作品を選び、必要素材を渡して製作を依頼する。
- 「話す」は通常のNPC会話として扱い、当日のA/B/C会話回数ルールに従う。
- **「製作を頼む」は通常会話A/B/Cとは別枠**とし、通常会話回数を消費しない。

### 製作単位

- 1回の製作依頼につき、選択できる製作レシピは**1種類だけ**とする。
- 選択した製作レシピは、1回の依頼で**複数個を製作可能**とする。
- 製作数量に共通の上限は設けない。
- 必要素材は、**レシピ1個分の必要量 × 指定数量**を必要とする。
- 異なる製作レシピを1回の依頼へ混在させることはできない。

### 完成品の収納

- 完成品は、完成品に設定されたフリーポケットカテゴリへ収納する。
- 製作確定前に、指定数量分の完成品を収納できるだけの**完成品カテゴリの空き枠**があるか確認する。
- 必要な空き枠が不足している場合は、その数量では製作を確定できない。
- 製作後にあふれた完成品だけ失う、別枠へ退避する、といった例外処理は設けない。

### 確定・消費タイミング

- 基本フローは、`製作レシピ選択 → 数量指定 → 必要素材・製作料金・空き枠確認 → 最終確認 → 支払い・必要素材消費 → 製作 → 完成品取得` とする。
- **最終確認まではジェニーも素材も消費しない**。
- 所持ジェニー不足、必要素材不足、完成品カテゴリの空き枠不足の場合は確定できず、消費も発生しない。
- 指定数量分の必要素材をまとめて消費する。

### 時間処理

- 作業場で製作を依頼しても、**ゲーム内時間は進行しない**。

### 営業時間

- 作業場の営業時間は**作業場ごとに個別設定**する。
- 営業時間外は「製作を頼む」を利用できない。

### 追加サービス

- 修理・強化・加工・鑑定その他の追加サービスは、**作業場の共通仕様としては設けない**。

# ブック

## 基本構造【確定】

- BOOKは**見開き2ページ構成**で表示する。
- ページ移動は**左右スワイプ**を基本とする。
- 1回のスワイプで**見開き1組ぶん**進む／戻る。
- 左右の物理ページはそれぞれ個別のページ番号を持つ。
- BOOK全体は**番号付きの物理ページ99ページ**を基準とする。
- BOOKを最初に開いた時だけ、左側に**番号を持たない空白ページ**があり、右側が1ページ目のタイトルページになる。
- 1ページ目は番号自体を内部的には持つが、画面上ではページ番号を表示しない。
- それ以降のページではページ番号を表示する。
- **99ページ目の後ろに、ページ番号を持たない終端見開きを1つ置く。** この2ページは99ページ構成には含めない。
- 各セクションのページ範囲は固定とし、所持数・記録数・依頼数などによって後続セクションの開始ページをずらさない。
- カード詳細、記録詳細、QUESTION詳細、依頼詳細、レシピ詳細などはBOOKの物理ページとは別の詳細UIとして開き、詳細UIにはBOOKのページ番号を付けない。

## ページ構成【D3確定／2026-09-17順序・正式ラベル更新】

| ページ | BOOK内正式ラベル | 内容 | 物理ページ数 |
|---|---|---|---:|
| 1 | UNTOLD | タイトル | 1 |
| 2–3 | GM | ゲームマスターのメッセージ | 2 |
| 4–5 | INDEX | 目次 | 2 |
| 6–17 | SPECIFIED POCKET | 指定カード | 12 |
| 18–49 | FREE POCKET | フリーカード／所持品 | 32 |
| 50–69 | RECORD | 記録 | 20 |
| 70–89 | QUEST | 依頼 | 20 |
| 90–91 | MAP | 地図 | 2 |
| 92–93 | QUESTION | 問い | 2 |
| 94–95 | RECIPE | レシピ | 2 |
| 96–97 | SAVE | セーブ | 2 |
| 98–99 | SETTINGS | 設定 | 2 |
| 番号なし | — | 終端見開き | 2（99ページ外） |

- 上記をBOOK全体の最終ページ構成とする。
- 指定カード、フリーカード、RECORD、QUESTの既存容量は削らない。
- MAP、QUESTION、RECIPE、SAVE、SETTINGSは1見開きを機能入口として使用し、必要な増加データはスクロール一覧・詳細UI等で扱う。
- **番号付きページは99ページのまま維持する。終端見開きは番号外とし、100・101ページ等として数えない。**
- v1で新しいBOOKセクションを追加する場合は、既存セクションを暗黙にずらさずページ構成変更として明示的に扱う。

## BOOK内正式ラベル【確定】

- BOOK内の主要セクション名は、ゲーム内での扱いと一致する**英字ベースの正式ラベル**へ統一する。
- 正式ラベルは `UNTOLD / GM / INDEX / SPECIFIED POCKET / FREE POCKET / RECORD / QUEST / MAP / QUESTION / RECIPE / SAVE / SETTINGS` とする。
- Wiki本文では説明のため日本語の「記録」「依頼」「地図」等を併記してよいが、BOOKの見出し・INDEX上の項目名は上記英字ラベルを優先する。
- 終端見開きは機能セクションではないため正式ラベルを持たない。
- 表示文面全般の実装前レビュー規則は `pages/development/production-workflow.md` を維持する。ただし本項で確定したセクション名自体はユーザー承認済みの正式ラベルとして扱う。

## 配置順の基準【確定】

- 冒頭の `UNTOLD / GM / INDEX / SPECIFIED POCKET / FREE POCKET` と、末尾の `SAVE / SETTINGS` は固定する。
- その間は、通常プレイでBOOKから直接開くと予想される頻度を基準に、`RECORD → QUEST → MAP → QUESTION → RECIPE` の順とする。
- MAPは通常画面のミニマップから直接開けるため、BOOK物理ページ上では使用頻度だけを理由に中央へ置かず、後ろ寄りの90–91ページへ置く。
- QUESTIONとRECIPEは、探索中に常時参照する機能ではなく、材料が揃った時や施設利用前後など意図的に開く機会が中心のためMAPより後ろへ置く。
- SETTINGSのさらに後ろには番号なし終端見開きを置き、BOOKの機能一覧を「設定画面で唐突に終わる」見え方にしない。

## タイトル「UNTOLD」の意味【方向性確定／開示方法はD4】

- 「UNTOLD」はゲームタイトルであると同時に、作中設定上もBOOKに与えられた名称。
- 命名者はゲームマスター。
- 序盤では主に「まだ知られていないもの／まだ語られていないもの」。
- 物語進行により「語られず、記録されなかったもの／語られることがなくなったもの」が重なる。
- 世界の真相へ近づくにつれ「語ること・記録することそのものを奪われた世界」へ接続する。
- 主人公が探索・記録・収集する行為そのものにも名称の意味を重ねる。
- 主人公はUNTOLDという語自体の一般的意味は理解できるが、BOOKの命名意図までは知らない。
- 具体的な再文脈化場面・台詞はD4で設計する。

## 1ページ目タイトルページ【確定／視覚調整値は実装調整】

- 表示する文字情報は**「UNTOLD」のみ**。
- 副題、説明文、署名等は追加しない。
- 本文より少し大きい程度。巨大ロゴにはしない。
- ページ中央よりやや上、横中央を基本とする。
- 手書き風ではなく整った活字調、細めのセリフ体を基本とする。
- 文字色は真っ黒ではなく、わずかに褪せた濃色。
- 紙色は軽い生成り。ごく薄い繊維感・自然な色ムラを持たせる。
- 四辺に装飾枠線を置かない。
- 綴じ目には弱い陰影と紙の湾曲感を持たせる。
- 字間はわずかに余裕を持たせるが、ロゴ的に大きく広げない。
- タイトル位置は物理中心より見た目上の中心を優先する。
- 具体フォント、字間、色、陰影量は上記方向を崩さない範囲で実機調整できる。
- 紋章・シンボル等の追加はv1必須仕様にしない。採用する場合はアート方向の明示変更として扱う。

## BOOKを開く位置【確定】

- 同一ゲームセッション中は最後に閉じた見開きを記憶する。
- 同一セッション中の再オープンではそこから再開する。
- ゲーム終了・再起動後にBOOKを開く場合は**INDEX 4–5ページ**から開始する。

## BOOKを閉じる操作【確定】

- BOOK外側の右下付近に文字ボタン「閉じる」を置く。
- 外側背景タップでも閉じる。
- BOOK内部のページ・カード・RECORD・QUESTION・QUEST・SETTINGS等の操作と競合させない。

## INDEXへ戻る操作【確定】

- BOOK外側の左下付近にINDEXへ戻る固定操作を置く。
- 押すと4–5ページへ移動する。
- 付箋タブとは別系統の固定操作。
- ボタン自体の最終表示文面は実装前文面レビュー対象とする。

## 終端見開き【確定】

- SETTINGS 98–99ページの次に、左右2ページとも**ページ番号を持たない終端見開き**を1つ置く。
- SETTINGSからさらに1回右へめくることで到達する。
- この2ページは番号付き99ページの外側にあり、100・101等の内部ページ番号をプレイヤーへ与えない。
- 機能セクションではないため、INDEXには載せない。
- 付箋タブの飛び先は番号付きページを指定する現行仕様を維持し、終端見開きを直接指定する対象にはしない。
- 通常状態では、**文字・ボタン・カード枠等を置かない、ほぼ無地の後見返し**として扱う。
- 紙色・綴じ目・質感はBOOK本体と連続させ、SETTINGSが本そのものの最終面に見えないよう余韻を作る。
- 将来、物語終盤や99枚達成後の演出をこの見開きへ追加する余地は残すが、現時点では具体内容を確定しない。
- BOOK外側に常設するINDEX／閉じる等の共通操作は、この見開きでも通常どおり利用できる。

## RECIPE【D3確定】

- 94–95ページの1見開き。
- BOOK内の通常RECORDとは別の**習得済みレシピ専用領域**。
- 上部で**料理／製作**を切り替える。
- 未習得レシピを表示せず、総数も表示しない。
- 習得済み一覧は見開き内で縦スクロールできる。
- 一覧項目には名称だけを基本表示し、選択すると物理ページ外のレシピ詳細UIを開く。
- 料理詳細：料理名、必要素材、必要数、料理効果。
- 製作詳細：製作品名、必要素材、必要数、完成品内容。
- レシピの習得・製作ルールは `pages/systems/recipes.md` を正本とする。

## 付箋タブ【確定】

### 基本

- 任意設定できる付箋型ショートカットを最大**5個**。
- 使用中タブはBOOK右端に縦並び。
- 設定画面の順番を上から下へ反映する。

### 設定画面

- INDEX内の付箋タブ設定操作から専用画面を開く。
- 5枠を最初から表示し、未使用枠は空き枠として示す。
- 使用中枠では名称、ページ番号、色、並び順を変更可能。
- 削除して空き枠へ戻せる。

### タブ名

- 自由入力、最大**4文字**。

### 飛び先

- BOOKのページ番号だけを指定する。
- 押すと指定ページを含む見開きへ移動する。

### 並び替え

- 「↑」「↓」ボタンで変更する。

### 色【D3確定】

| プリセット | 基準色 |
|---|---|
| 赤 | `#B46A62` |
| 青 | `#5E789B` |
| 緑 | `#6F8A68` |
| 黄 | `#C39A52` |
| 紫 | `#846F96` |

- 生成り紙面から識別できる低彩度を基本とする。
- 色に機能上の意味を持たせない。
- 実機視認性に応じ、5色の系統を維持したまま明度・彩度を調整可能。

## 付箋タブ解放チュートリアル【確定／具体内容はD4】

- BOOK取得直後から表示せず、専用チュートリアル後に解放する。
- 複数候補ページのうち最初に条件成立した1ページだけで、ゲームマスターが雑に差し込んだ紙のイベントを発生させる。
- 各セクション先頭ページそのものは候補にしない。
- 完了後、他候補では再発生しない。
- 意図は「毎回ページをめくるのは面倒なので付箋を使えばいい」。
- このイベントのみ、GMメッセージ後に付箋操作の明示的なシステム説明を行う例外を認める。
- 説明完了後にタブ設定機能を解放し、解放前は付箋UI自体を表示しない。
- 候補数・ページ番号・具体台詞・紙の見た目はD4で決める。

## QUEST【D3確定／2026-09-17位置・正式ラベル更新】

### ページ構成

- 70–89ページ、20物理ページ。
- 1ページ6件、1見開き12件、全体120件ぶんの表示余地。
- 正式依頼総数はD4のコンテンツ量として決める。

### 一覧

- 未完了／完了済みを1つの統一一覧で表示。
- 標準は**未完了を先、完了済みを後**。
- 各グループ内は元の登録順。
- 追跡中は小さな追跡マーク、完了済みはチェックマークを表示し、色だけに依存しない。
- 未発見ダミー枠・全件数表示はしない。
- 並び替えは**状態順／登録順**の2種。標準は状態順。
- 基本表示は依頼名／依頼者＋状態アイコン。
- 現在目的、受注場所、報酬等は詳細UI。

### 詳細・追跡

- 把握済み内容、現在目的、依頼主、受注場所等を表示する。
- 未知の攻略手順をBOOKが補完しない。
- 報酬は提示済み内容だけ表示し、未提示なら欄を出さない。
- 複数未完了依頼を保持できるが、HUD追跡は1件。
- 新規登録で追跡対象を自動変更しない。
- 詳細から手動変更可能。
- 追跡依頼完了時、他の未完了依頼があれば完全ランダムで1件を自動追跡。0件なら追跡なし。

### 未完了依頼上限

- 同時にBOOKへ登録できる未完了依頼は最大**12件**。
- 完了済みは上限に数えない。
- 12件時の新規依頼は登録せず、短いシステム文で上限だけ伝える。
- 期限切れ仕様がない限り、上限で登録できなかった依頼は後から再度受けられる状態を維持する。
- 未完了依頼を任意削除して枠を空ける機能は設けない。完了で枠を空ける。
- D4では必須本編進行が12件上限で詰まらないよう、イベント進行と依頼登録を分離するか登録可能状態を保証する。

### 完了判定

- 完了フラグを立てる報告会話位置は依頼ごとに設定する。
- 行動達成だけで共通自動完了にはしない。

## 記録の世界内原理【確定】

- 会話等は自動記録ではなく、プレイヤーが残したい情報だけを記録する。
- 主人公が物理的に筆記するのではなく、「記録したい」と意識した内容をBOOKが受け取って残す。
- 記録対象文の選択はプレイヤー操作で行う。
- 記録という使い方はGMから説明される。
- BOOKに近くのカードを自動感知する能力は持たせない。

## タイトル見開きとNo.0【確定】

- No.0「主人公」は冒頭見開き左側の番号なし空白ページへ表示する。
- 初回から99/99達成までは空白のまま。
- 右側1ページ目「UNTOLD」はNo.0出現後も変更しない。
- 99/99を明確に完結した後、後続展開でBOOKを再び開いた際に最初の見開きを表示し、左側へNo.0を出現させる。
- 最初からあった空白が、世界を記録してきた主人公のための**99枚の枠外**だったと意味を反転させる。
- No.0は番号付き99ページへ追加せず、99ページ構成を変更しない。
- 主人公名・画像・説明文、出現直前の具体演出はD4で決める。
